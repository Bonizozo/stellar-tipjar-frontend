# `typedRoutes` safety-net audit (issue #602)

## TL;DR

- `npm run typecheck` **passes cleanly (exit 0).**
- `typedRoutes` **is functional** — a build-time route type union is generated and `tsc` *does* reject invalid routes — **but only after `next build` has generated `.next/types`, and only for multi-segment paths.**
- Three gaps mean broken route references can still ship silently: (1) the check is **absent on a fresh checkout with no prior build**, (2) the top-level **`/[locale]`** route makes every single-segment path type-valid, and (3) **16 explicit casts** bypass the check outright — one of which pushed **arbitrary voice input** as a route (fixed in this PR).

## Method

All claims below were verified against the current tree by planting probe files and running `npm run typecheck` (`tsc --noEmit`). Each probe was sanity-checked (an unrelated `string→number` error was confirmed to fire) so a "no error" result means the route specifically was accepted, not that the file was skipped.

## Findings

### 1. `typecheck` passes — and the type is real

`tsc --noEmit` exits 0. `.next/types/routes.d.ts` generates a literal union of every real route (`/marketplace`, `/tips`, …), and `import type { Route } from "next"` resolves to it. Assigning a non-route to a `Route`-typed value is rejected — e.g. `const r: Route = "/"` fails, correctly, because there is **no root `app/page.tsx`** (home is served via the `/[locale]` segment + middleware, so `/` is a `LayoutRoute`, not an app `Route`).

### 2. The check only exists after a build (CI gap)

`.next/types` is generated by `next build` / `next dev`, not by `tsc`. With `.next/types` removed (a fresh checkout that has not built), a clearly-invalid `<Link href="/no/such/multi/segment">` **passes** typecheck. So any pipeline that runs `typecheck` **without building first** enforces nothing.

> Verified: remove `.next/types` → the multi-segment bogus link compiles clean (exit 0). Restore it → the same link fails with `TS2322`.

**Recommendation:** ensure `next build` (or `next typegen`) runs before `typecheck` in CI, so the route types exist when `tsc` runs.

### 3. `/[locale]` swallows every single-segment path

Because a top-level `/[locale]` dynamic route exists, `RouteImpl` accepts any `/${slug}` single segment. So `<Link href="/dashbord">` (a typo) type-checks as a valid "locale" and is invisible to the safety net; only multi-segment typos (`/dash/bord`) are caught. This is inherent to having a catch-style top-level dynamic segment — worth documenting so contributors don't over-trust single-segment link checking.

### 4. Explicit bypasses (16 sites)

`typedRoutes` cannot see through a cast. Current bypasses:

| Category | Sites | Note |
|---|---|---|
| **Arbitrary user input** (highest risk) | `useVoiceCommands.ts` `go to <page>` | Pushed transcribed speech as `/${page}`. **Fixed in this PR** (allowlist validation). |
| **Whole-router cast** | `Pagination/index.tsx:113` `(router as any).push(url)` | Disables typing on the entire call. |
| **Data-driven `href={x as any}`** | `settings/page.tsx:86`, `BottomDock.tsx:84`, `Breadcrumb/BreadcrumbItem.tsx:33`, `Breadcrumb/index.tsx:98`, `MegaMenu.tsx:34,84`, `MobileMenu.tsx:232`, `NotificationCenter.tsx:85`, `ProfileCompletionIndicator.tsx:114` | Link field is typed `string`; typing it as `Route` at the source would restore checking. |
| **Dynamic path / query string** | `LanguageSwitcher.tsx:35`, `useSearchParams.ts:26,46` | Locale-swapped path / pathname+query built at runtime. |
| **Justified (`/` has no typed route)** | `offline/page.tsx:33`, `Navbar.tsx:232`, `useVoiceCommands.ts:107` | Legitimate — `/` is not an app `Route`; keep, but comment. |

**Recommendation (follow-up, out of scope here):** type the link fields in the menu/breadcrumb data as `Route` instead of `string` to remove the `as any` casts at the source, and replace `(router as any).push` with a typed push. These are behaviour-neutral refactors best done in a dedicated PR.

## What this PR changes

`src/hooks/useVoiceCommands.ts`: the `go to <page>` voice command no longer pushes `/${page}` (arbitrary transcript) straight into the router. It now validates the spoken word against an explicit `VOICE_NAV_ROUTES` allowlist (typed `Record<string, Route>`, which the compiler *does* enforce). Unknown targets get spoken feedback instead of a navigation. The `go home` case keeps a single, documented `as Route` cast because `/` is genuinely not a typed route.
